# Environment validated at runtime, with missing values failing at first use

All environment variables are read through one Zod-validated configuration module, split into a public group (Supabase URL and publishable key, inlined into the browser bundle) and a server-only group guarded against client imports; no service role or secret key is declared. Validation is deliberately kept out of the build configuration and does not treat a missing required variable as a startup error: when a Node.js server process starts, the Next.js instrumentation hook validates every variable that is set, so a malformed value fails fast, while a missing required value fails when its group is first used, with an error that names the variable and never echoes its value. An empty or whitespace-only value counts as unset, so an `.env.example` copied unchanged behaves like no env file. We chose this over failing the build or the startup on any missing variable because the squad's gates, ticket worktrees and the Playwright tracer must run in a fresh checkout with no env file and no Supabase project; production still fails loudly on its first Supabase use. The Hadith API base URL defaults to the jsDelivr endpoint already in use, so it is never missing.
